# broll - 릴스 조립기 (v2.1)

**작업 위치:** 이 저장소
**갱신:** 2026-08-10 - v1(범용 AI 에디터) 폐기 → v2(릴스 조립) → v2.1(소스 안에서 컷 선택 추가)

---

## 0. 무엇을 만드는가

**네가 주는 것:** 자막 줄 목록 + 각 줄에 쓸 영상 소스(통짜) + 녹음 파일 하나
**도구가 하는 것:** ① 녹음에 자막을 정렬해 줄별 타이밍을 뽑고 ② 각 소스 **안에서 어느 몇 초를 쓸지 골라** ③ 배치하고 자막을 얹어 내보낸다
**캡컷이 하는 것:** 음악, TTS, 최종 마감

파이프라인의 절대다수는 결정론적 계산이다. 모델이 필요한 지점은 **딱 하나** - "이 자막엔 이 소스의 어느 부분이 어울리는가". 그것도 릴스 한 편에 **호출 1회**, 인터랙티브 Claude Code 안에서 일어나므로 구독 한도로 커버된다. 영상 한 편 뽑을 때마다 토큰이 줄줄 새는 구조가 아니다.

## 1. 구독만으로 가는 법 (요구사항 1·2)

| 실행 방식 | 구독 | 비고 |
|---|---|---|
| **Claude Code 터미널 인터랙티브** | O | Pro/Max 구독 한도 그대로 |
| **Codex CLI (`Sign in with ChatGPT`)** | O | ChatGPT Plus/Pro 사용량 공유, API 키 불필요 |
| `claude -p`, Agent SDK, GitHub Actions | X | 2026-06-15부터 별도 크레딧 풀 (API 요율) |
| 앱 안에 AI 사이드바 넣고 모델 호출 | X | 편집 한 번마다 과금 - levelsio 방식이 정확히 이것 |

**지켜야 할 규칙 하나:** 만드는 앱 안에 모델 호출을 넣지 않는다. 앱은 CLI + 미리보기이고, 판단이 필요한 순간엔 터미널의 Claude Code가 도구를 호출한다.

**Claude / ChatGPT 분담 (솔직한 버전):** 이 파이프라인에 모델이 두 개 필요하진 않다. 실질적 이득은 **한도 분산** - Claude 한도가 차면 Codex CLI로 같은 저장소에서 이어서 작업. 대본·훅 카피 다듬기는 ChatGPT 앱에서 하고 자동화하지 않는다.

## 2. 입력 포맷 (요구사항 3)

한 편 = 파일 하나.

**실측으로 확인된 네 습관 (0806·0703·0626 프로젝트):** 녹음을 통짜 한 파일이 아니라 **줄 단위로 따로** 한다 (0806은 8줄에 녹음 8개, 0703은 26개). 그리고 녹음 총 길이 39.2초 → 타임라인 21.6초. 즉 **각 녹음에서 앞뒤 무음과 버벅인 부분을 잘라 쓰고 있다.** 그게 자동화할 노동이다. 그래서 입력 포맷을 줄별 녹음 기준으로 잡는다.

```yaml
# reels/250810-편집자동화.yml
template: 0806               # 이 프로젝트를 스타일 템플릿으로 복제
ratio: "9:16"

lines:
  - t: "이거 모르면 진짜 손해예요"
    rec: rec/음성 녹음2.aac    # 이 줄 녹음 (없으면 무음 길이 추정)
    src: clips/hook.mp4
  - t: "16분짜리 편집에 4시간 걸렸는데"
    rec: rec/음성 녹음3.aac
    src: clips/timeline.mov   # 인점 생략 → 도구가 알아서 고름
    prefer: "타임라인 빽빽한 화면"   # 고를 때 참고할 힌트 (선택)
  - t: "지금은 5분이면 끝나요"
    rec: rec/음성 녹음4.aac
    src: clips/fast.mp4
    from: 2.4                 # 인점을 못 박고 싶을 때만
    cuts: 2                   # 이 줄을 2컷으로 (기본: 길이 보고 자동)
```

**빌드 (`broll build reels/xxx.yml`)**

1. **줄별 트림** - 각 `rec`에서 `t`를 강제 정렬해 **실제 말한 구간**만 남긴다. 앞뒤 무음 제거, 여러 번 읽었으면 마지막 클린 테이크 선택, 앞뒤 20~30ms 페이드
2. **타임라인 배치** - 트림된 녹음을 순서대로 이어 붙여 줄별 `[start, end]` 확정
3. **컷 선택** - 각 소스 안에서 그 길이만큼 어디를 쓸지 결정 (§3)
4. **자막** - 줄 하나 = 자막 세그먼트 하나. 너무 길면 어절 단위로 2행 분할
5. **출력** - ① 미리보기 mp4(자막 번인) ② 캡컷 드래프트(템플릿 복제)

**정렬 방식:** 프리 ASR이 아니라 **강제 정렬(forced alignment)**. 정답 텍스트를 이미 알고 있으니 "한국어 ASR 오타" 문제가 아예 발생하지 않는다. 줄별 녹음이면 문제가 더 쉬워진다 - 한 파일 안에서 한 줄만 찾으면 되니까. 구현은 whisper.cpp 단어 타임스탬프 → 대본과 문자 단위 편집거리 정렬. 경계가 흔들리면 MFA(한국어 지원, 경계 오차 15ms 이하)로 업그레이드.

## 3. 컷 선택 - 소스 안에서 몇 초를 쓸까 (요구사항 5)

자막 줄의 길이 `d`가 정렬에서 나온다. 소스 `src` 안에서 `[s, s+d]`를 고르는 문제다.

### 1단계 - 결정론적 후보 추리기 (모델 없음)

- **샷 경계 존중.** PySceneDetect로 소스의 컷을 찾고, 선택 구간이 샷 경계를 가로지르지 않게 한다. 이걸 안 지키면 한 자막 안에서 장면이 툭 바뀌는데, 가장 티 나는 실수다.
- **프레임 점수:** 선명도(라플라시안 분산) · 모션 크기(프레임 차분) · 노출 · 얼굴 유무.
  움직임이 있되 과하지 않은 구간을 선호. 흔들림·블러·암부는 감점.
- **가장자리 감점.** 소스 앞뒤 0.3초는 카메라가 정리되는 구간이라 깎는다.
- 길이 `d` 슬라이딩 윈도우로 점수화 → **상위 3개 후보** 확보.

여기까지가 기본값이다. 모델 없이도 항상 동작한다.

### 2단계 - 자막과 맞는 걸 고르기 (릴스 한 편당 모델 호출 1회)

- 후보마다 대표 프레임 3장을 뽑아 **릴스 전체를 컨택트 시트 한 장**으로 묶는다.
- Claude에게 자막 목록 + 시트를 주고 "줄마다 어느 후보가 어울리는지" 한 번에 묻는다. 자막 15줄이어도 **호출 1회**.
- `prefer` 힌트가 있으면 그걸 우선한다.
- 응답이 없거나 건너뛰면 1단계 최고점으로 자동 확정. **모델은 품질 향상용이지 필수 경로가 아니다.**

### 3단계 - 컷 리듬

- 자막 한 줄이 **2.5초를 넘으면 자동으로 2컷 분할**. 릴스 문법상 한 화면이 오래 붙어 있으면 늘어진다. `cuts: 1`로 끄고, `cuts: 3`으로 더 쪼갠다.
- **컷 지점은 정렬에서 나온 어절 경계에 스냅한다.** 말 중간에 화면이 안 바뀐다 - 정렬을 이미 했기 때문에 공짜로 얻는 자연스러움이고, 손으로 맞추면 제일 귀찮은 부분이다.
- 같은 소스를 연속으로 두 줄에 쓰면, 두 번째는 앞에서 쓴 구간을 피해서 고른다(같은 그림 반복 방지).

### 검수 루프

빌드가 끝나면 각 컷의 **첫 프레임을 이어붙인 스토리보드 PNG**를 같이 뱉는다. 미리보기 mp4를 다 보지 않고도 한 장으로 "3번이 이상한데" 판단이 되고, 그 상태로 Claude에게 "3번 다시 골라줘"라고 하면 된다.

## 4. TTS와 음악 (요구사항 4) - 핵심 판단

### 결론: 최종 산출물을 mp4가 아니라 **캡컷 드래프트**로 내보낸다

"렌더된 mp4를 캡컷에 넣고 음악·TTS 추가"도 동작은 한다. 그런데 **한 번 구워지면 컷과 자막 타이밍을 못 고친다.** 릴스는 음악 비트에 컷을 맞추는 경우가 많은데 mp4로는 불가능하고, TTS로 목소리를 갈아끼우면 타이밍이 통째로 어긋난다.

드래프트로 넘기면 컷·자막·타이밍이 전부 살아있는 상태로 캡컷이 열리고, 음악만 얹으면 된다. 어차피 **캡컷 음원 라이브러리는 캡컷 안에서만 라이선스가 유효하고 추출도 안 되니** 음악은 캡컷에서 붙이는 게 맞다. 그 전제를 받아들이면 드래프트 출력이 명백히 우위다.

### TTS: 두 가지 모드

**모드 A - 내 목소리 (기본)**
녹음 → 강제 정렬 → 타이밍 확정 → 컷 선택 → 드래프트 출력 → 캡컷에서 음악만 추가. 음악은 타이밍을 바꾸지 않으니 깔끔하다.

**모드 B - 캡컷 TTS (가끔)**
순서를 뒤집는다.

1. 캡컷에서 자막 텍스트만 입력하고 TTS 생성 → 저장
2. `broll build --from-capcut <draft>` 가 그 드래프트를 **읽어서** 자막 세그먼트 타이밍과 TTS 오디오를 가져온다
3. 각 구간에 컷을 골라 채워 넣고 드래프트를 다시 쓴다
4. 캡컷에서 열어 음악 추가

정렬조차 필요 없다 - 캡컷이 이미 타이밍을 갖고 있으니까.
**D0에서 확인됨:** TTS 오디오는 `<draft>/textReading/*.wav` 로 로컬 저장되고, 오디오 트랙 세그먼트에 타이밍이 전부 들어있다(0718 프로젝트 33개 확인). 즉 모드 B는 **가정이 아니라 확정된 경로다.** 가이드 녹음 같은 차선책은 필요 없다.

### 음악 고르기

자동화 대상이 아니라 **수집** 대상이다. 지금처럼 남의 영상 보며 고르되 `music.md`에 후보를 적립해라 - 트랙명 / BPM / 무드 / 어디서 봤는지 / 썼는지. 다음 편에서 고르는 시간이 준다.
비트에 컷 맞추기는 일단 캡컷에서. 나중에 필요하면 librosa 비트 트래킹(무료)으로 드래프트에 비트 마커를 찍고, 컷 지점을 어절 경계 대신 비트에 스냅하는 옵션을 넣으면 된다.

## 5. D0 - 검증 완료 (2026-08-10 실측)

**환경:** CapCut 9.1.4443 (앱), 드래프트 `new_version` 173~181, macOS. 실제 프로젝트 11개 확인.

### 결과: 트랙 A 확정

| 확인 항목 | 결과 |
|---|---|
| ① 드래프트 평문인가 | **통과.** 단 파일명이 `draft_content.json`이 아니라 **`draft_info.json`** (9.x부터). 376KB 평문 JSON, 암호화 없음 |
| ② 라이브러리로 쓸 수 있나 | **pyCapCut은 안 씀** (아래) |
| ③ TTS 오디오 로컬에 남나 | **통과.** `<draft>/textReading/*.wav` 로 저장되고, 오디오 트랙에 세그먼트 타이밍이 전부 있음. `tone_speaker`·`tone_effect_name` 등 보이스 정보도 JSON에 남음 |

### ② 결론: pyCapCut 대신 **기존 프로젝트를 템플릿으로 복제**

pyCapCut/pyJianYingDraft는 `draft_content.json` 스키마 기준이고, 지금 캡컷은 `draft_info.json`을 쓴다. 억지로 맞추는 것보다 **네 기존 프로젝트를 복사해 세그먼트만 갈아끼우는 쪽이 안전하고 결과도 낫다.**

이유가 더 있다 - 템플릿을 쓰면 **자막 스타일·폰트·트랙 구성·효과를 코드로 재현할 필요가 없다.** 0806 프로젝트만 봐도 텍스트 트랙 4개(메인 자막 + 강조 레이어), 효과 112개, HSL·애니메이션이 다 들어있다. 이걸 JSON으로 재생성하려 들면 끝이 없다. 복제하면 공짜다.

```
broll build → 템플릿 프로젝트 폴더 복사
             → draft_info.json 의 video/text/audio 세그먼트만 교체
             → 새 이름으로 저장 → 캡컷에서 열림
```

**원본은 절대 건드리지 않는다.** (ye.bu.bu 사례에서도 이게 안전장치였다)

### 실측으로 파악된 스키마

```
draft_info.json
├ canvas_config: {width:1080, height:1920}   # 릴스 세로
├ duration(us), fps
├ tracks[]: type = video | text | audio
│   └ segments[]: material_id
│                 target_timerange {start, duration}   # 타임라인 위치
│                 source_timerange {start, duration}   # 소스 안 인점 ← 컷 선택이 쓰는 곳
│                 speed
└ materials
    ├ videos[]:  path, type
    ├ texts[]:   content(JSON 문자열), font_name, font_size
    ├ audios[]:  type = record | music | sound | text_to_audio
    └ beats[]:   비트 정보 슬롯 (지금은 비어있음, 나중에 비트 스냅에 쓸 자리)
```

`source_timerange.start`가 정확히 §3 컷 선택이 채워 넣을 값이다.

**M2를 M3보다 먼저 두는 이유:** M1+M2면 `from:`을 손으로 적어서라도 **끝까지 도는 파이프라인**이 생긴다. 실제 릴스를 한 편 뽑아봐야 컷 선택 점수 함수를 뭘 기준으로 짜야 할지 알 수 있다. 순서를 바꾸고 싶으면 말해줘 - M3를 먼저 해도 된다.

**검증에 쓸 기준 데이터가 이미 있다.** 0806(8컷 21.6초)은 네가 손으로 만든 정답지다. 같은 소스·같은 녹음·같은 자막을 넣고 돌려서 `source_timerange`가 네가 고른 인점과 얼마나 붙는지 보면 컷 선택 품질이 숫자로 나온다.

M5 후보: 얼굴 기준 9:16 자동 크롭, 소스 라이브러리 재사용(같은 클립 어디에 썼는지 기억), 자막 스타일 프리셋, 줄 순서 바꾸면 전부 재계산.

**M2까지가 제품이고 M3가 네가 원한 것이다. 나머지는 가속기다.**

## 7. 스택

| 층 | 선택 | 이유 |
|---|---|---|
| 에이전트 | Claude Code 인터랙티브 (+ Codex CLI 예비) | 구독 인증. Agent SDK/`claude -p`는 별도 과금 |
| 정렬 | whisper.cpp 단어 타임스탬프 + 대본 편집거리 정렬 | 정답 텍스트가 있으니 ASR 정확도가 문제되지 않음 |
| 정렬 (업그레이드) | MFA 3.x 한국어 | 경계 오차 15ms 이하 |
| 샷 경계 | PySceneDetect 0.7 | 컷이 장면 전환을 가로지르지 않게 |
| 프레임 점수 | OpenCV (선명도·모션·노출) | 로컬·무료 |
| 컷 선택 판단 | Claude 비전, 컨택트 시트 1장, 편당 1회 | 없어도 동작(결정론적 최고점 폴백) |
| 조립·렌더 | ffmpeg | 미리보기용. 최종 렌더는 캡컷 |
| 자막 번인 | ffmpeg + libass | 라이선스 무료 |
| 캡컷 출력 | **템플릿 프로젝트 복제 + `draft_info.json` 세그먼트 교체** (자체 구현) | pyCapCut은 구버전 `draft_content.json` 스키마 기준이라 안 맞음. 복제하면 자막 스타일·효과가 공짜로 따라옴 |

**v1에서 뺀 것:** Remotion(최종 렌더를 캡컷이 하므로 이득 없음), MCP 서버(CLI로 충분), 테이크 선택·전체 자동 컷편집(기획을 네가 하니까 불필요). 긴 영상 컷편집을 하게 되면 그때 v1 문서를 다시 꺼내면 된다.

## 8. 위험

- **드래프트 포맷은 캡컷 업데이트에 깨진다.** 그래서 미리보기 mp4 경로를 항상 같이 유지한다. 드래프트가 깨져도 영상은 나온다.
- **컷 선택은 취향 문제다.** 점수 함수로 100%는 안 된다. 그래서 스토리보드 PNG로 한눈에 검수하고 한 줄만 다시 고르는 루프가 핵심이다. "완벽히 알아서"가 아니라 "3개만 고쳐주면 됨"을 목표로 잡는다.
- **오디오 컷 경계.** 줄 사이를 다듬을 땐 20~30ms 페이드.
- **모드 B 타이밍 어긋남.** TTS 길이 ≠ 가이드 녹음 길이. 캡컷 우선 경로(역방향)가 정답, 가이드 녹음은 차선.
- **범위.** 실제 릴스를 한 편 뽑아보기 전에 기능을 늘리지 않는다.
